## Design guidelines for dashboards and data interfaces

When building dashboards, panels or any data-heavy UI, avoid the visual habits that make an interface look AI-generated. Favor clarity, hierarchy and function over decoration.

### DON'T USE

1. Purple/blue gradients or generic "tech" backgrounds
2. Neon on black
3. Glassmorphism (frosted-glass/blur cards)
4. Large or exaggerated drop shadows
5. An "eyebrow" (tiny all-caps label) above every heading
6. "Live" tags when the data isn't actually real-time
7. Colorful chips/badges on everything
8. A colored icon decorating every KPI
9. A green pill with an arrow (+12%) on every number
10. Emojis in headings and section titles
11. Sparkle icons (✨) or "AI Insights" sections
12. Donut charts with the total in the middle
13. Rainbow palettes in charts (one color per bar for no reason)
14. Generic titles that only name the chart ("Sales by month", "Overview")
15. Tiny sparklines nobody can read
16. Greetings like "Welcome back, John! 👋"
17. A colored stripe on the edge of cards
18. A decorative sidebar whose items lead nowhere
19. Filters that don't actually filter anything
20. "Insight" blocks with generic text nobody reads

### DO THIS INSTEAD

- Neutral background (white or very light gray) and at most one accent color, used only for what matters.
- Titles that state the takeaway, not the chart type (e.g. "Sales fell 8% in October, driven by the South region" instead of "Sales by month").
- Show change (↑/↓) only where the comparison matters, with the reference period stated.
- Single-color bar/line charts; highlight only the series or point that matters.
- Bars instead of donuts to compare parts of a whole.
- Thin borders or whitespace instead of shadows; typography as the main hierarchy tool.
- Every element on screen must do something: if a filter, menu or button doesn't work, leave it out.
- Analysis text only when it says something specific and actionable, with numbers.
- When in doubt, less: a sober, readable dashboard beats a pretty, generic one.
